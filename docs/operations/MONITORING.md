# CEOP 監視設計

## SLI / SLO（初期目標）

| SLI | 定義 | SLO |
|---|---|---|
| 可用性 | `/health/ready` 2xx の月間割合 | 99.5% |
| レイテンシ | `/api/v1/dashboard` の p95 | 500 ms |
| エラー率 | 5xx の全リクエスト比 | < 1% |
| バックアップ成功 | 直近 7 日間の成功数 | 7/7 |

## 監視項目

- liveness/readiness: `GET /health`、`GET /health/ready`（30 秒間隔、3 回失敗でアラート）
- 認証失敗率: 401/429 の急増（レート制限・パスワード攻撃の兆候）
- 監査ログ: `verify()` 破損、追記失敗
- リソース: CPU / メモリ / ディスク（SQLite ボリューム）・コンテナ再起動
- ログ: json-file ローテーション、ログ量の急増

## アラート

- P0: readiness 5xx 3 回連続、認証不能、監査ログ破損
- P1: エラー率 > 1%、ディスク使用率 > 80%、バックアップ失敗 2 回連続
- P2: レイテンシ SLO 超過、メモリ使用率 > 85%

通知先: 運用担当（PagerDuty / Slack / メール）を環境ごとに設定。本番環境の一意特定が
可能になった時点でアラートルールをデプロイします。
