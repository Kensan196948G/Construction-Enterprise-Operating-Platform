# CEOP セキュリティ対応手順

## 重大度定義

- P0: データ漏えい・破損・認証全停止・不正アクセス
- P1: 主要機能の欠落・高リスク脆弱性
- P2: 中リスク・可用性/UX 影響
- P3: 軽微

## P0 対応フロー

1. 影響範囲の特定（アクセスログ、監査ログ、DB、ネットワーク）とサービスの安全側停止
2. 証跡保全（ログ・スナップショットを変更せず退避）
3. 復旧（rollback / リストア）— `RUNBOOK.md` 参照
4. 報告（関係者、必要に応じて規制当局）
5. 根本原因分析と再発防止策の適用
6. 監査ログの整合性検証（`verify()`）と秘密のローテーション

## 秘密のローテーション

- `CEOP_JWT_SECRET`: 新値を生成 → 旧値で JWT 失効 → 環境変数更新 → 再起動
- API キー: `provision-api-key.ts` で新キー発行 → クライアント切替 → 旧キーを DB から削除
- 影響と手順だけを報告し、秘密の値をチャット・Issue・ログに書かない
