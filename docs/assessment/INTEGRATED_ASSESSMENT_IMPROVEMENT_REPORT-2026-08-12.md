## 3. 強み（17 件）

1. ランタイム依存ゼロ（node:http + node:sqlite）で脆弱性・保守面が小さい
2. Result 型・strict TS・例外を投げない設計（typecheck 0 error）
3. SHA-256 ハッシュチェーン監査ログ＋**検証 API/CLI/日次タイマー**（改ざん検知の自動化）
4. RBAC + テナント境界 + 非開示 404（IDOR 対策）
5. JWT（HS256・jti replay guard）+ API キー（HMAC + timingSafeEqual）+ 失効 API
6. ISO 9001/14001/45001/55001/19650 統合管理を 1 基盤で実装（migration 025・エイリアス 32 系統）
7. 連携先 6 システム Webhook（HMAC 署名）/イベントキュー/再送/冪等性/契約管理
8. 534 テスト + parity（FEATURE_INVENTORY 照合）+ E2E 6 + verify-restore（監査チェーン含む）
9. 日次バックアップ（VACUUM INTO）+ 保持ポリシー + 復元検証スクリプト
10. Prometheus/Grafana 監視スタック（loopback 限定・cap-drop）
11. バージョン一元管理（src/version.ts・package.json・Dockerfile・OpenAPI 整合テスト）
12. 本番稼働中・公開 URL スモーク・コンテナ ハーデニング適用を実測確認
13. 移行台帳・git bundle アーカイブ・Issue/PR 記録（IMS 吸収 P6）
14. シークレット非コミット（.env 分離・provision CLI・gitleaks CI・pnpm audit 0）
15. AI ガバナンス（promptHash のみ保存・evidenceRefs・PII 明示・誤回答対策・利用停止）
16. 運用文書（RUNBOOK/BACKUP/MONITORING/LEDGER）が実運用と一致
17. CI 全ジョブ成功・カバレッジ閾値（line 70/branch 60/function 70）・OpenAPI drift 検知

## 8. AI 評価と設計方針

- **現状**: AI は「統制」のみ実装（ai-actions の承認・根拠・PII・停止・監査）。推論ゼロ。
- **基本方針**: チャット目的化しない。時間削減・検索/判断支援・説明可能性・安全性・費用対効果で採否を判断。
- **AI 不要な領域**（ルール・検索で十分）: 番号採番、定期点検スケジュール、文書ステータス遷移、
  通知トリガー、監査チェーン検証、CSV 式インジェクション対策。
- **導入候補**: ①RAG ナレッジ検索（社内手順・過去是正、根拠=文書 ID・信頼度・引用付き）、
  ②構造化抽出（日報→工数/出来高、写真→種別）、③分類（不適合・ヒヤリの重大度）、
  ④予測（原価・工期）、⑤異常検知（安全指標・原価乖離）。
- **必須設計**: 人間承認ワークフロー（既存 ai-actions を活用）、権限制御（閲覧範囲と同一）、
  プロンプトインジェクション対策（入力をデータ扱い・出力検証・隔離）、PII 非保存（piiSensitive）、
  モデル/プロンプト/入出力の監査（promptHash・evidenceRefs 活用）、誤判定時の責任分界を
  利用規約と承認フローで明示、利用量・予算上限（1 ユーザー/月トークン上限）、停止手段
  （status=stopped を監査付きで即時適用）。
