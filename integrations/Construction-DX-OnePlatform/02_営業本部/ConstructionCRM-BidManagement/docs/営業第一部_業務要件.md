## 1. 部署概要

### 1.1 組織上の位置づけ
営業第一部は営業本部に属し、主に官公庁発注の港湾・海上工事を中心とした公共工事の受注活動を担う。国土交通省・地方整備局・港湾空港技術研究所等の発注機関との関係構築、入札対応、技術提案書作成が主要業務である。

### 1.2 部署ミッション
- 港湾・海上工事分野の公共工事受注目標の達成
- 発注機関との信頼関係構築・維持
- 総合評価方式入札における高得点の獲得
- 技術提案書の品質向上

### 1.3 主要メンバー構成
| 役職 | 人数（想定） | 主な業務 |
|------|-------------|---------|
| 部長 | 1名 | 受注戦略策定、主要発注者対応 |
| 課長 | 2名 | 入札管理、提案書統括 |
| 営業担当 | 4～6名 | 発注者訪問、情報収集、日報作成 |
| 入札事務 | 1～2名 | 入札書類作成、手続き管理 |

## 2. 現行業務フロー

### 2.1 案件情報収集業務
```
国交省等の発注見通し公表（年2回）
    ↓
発注情報の収集・整理（官報・入札情報サービス）
    ↓
対象案件の選定（部内会議）
    ↓
案件カードの作成（Excel管理）
    ↓
発注機関への訪問・情報収集
    ↓
営業日報の作成
```

**現行の課題**
- 発注見通しの手動チェックに時間がかかる
- 案件管理がExcelで属人化している
- 営業日報が紙or個別Excelで共有されにくい
- 過去の受注実績検索に手間がかかる

### 2.2 入札対応業務
```
入札公告の確認
    ↓
参加資格の確認（等級・地域・実績要件）
    ↓
入札参加決定（部長承認）
    ↓
総合評価方式の場合：技術提案書作成
    ↓
入札書・技術提案書の提出
    ↓
開札・結果確認
    ↓
受注 or 敗退分析
```

### 2.3 技術提案書作成業務
```
入札条件・評価基準の分析
    ↓
技術本部への技術相談
    ↓
過去の類似提案書の検索（ファイルサーバー手動検索）
    ↓
提案書ドラフト作成
    ↓
部内レビュー
    ↓
技術本部レビュー
    ↓
最終版作成・提出
```

**現行の課題**
- 過去提案書の検索が困難（ファイルサーバーに散在）
- 提案書作成に1件あたり1～2週間を要する
- 類似提案の知識が個人に蓄積し共有されない

## 3. 業務要件（詳細）

### 3.1 案件管理

#### 3.1.1 案件ライフサイクル管理
案件を以下のステータスで管理し、各段階での必要アクションを明確にする。

| ステータス | 定義 | 必要アクション |
|-----------|------|--------------|
| 情報収集中 | 発注見通しに計上された段階 | 発注機関訪問、詳細情報収集 |
| 検討中 | 入札参加を検討している段階 | 参加資格確認、社内審議 |
| 入札準備中 | 入札参加決定後 | 提案書作成、見積作成 |
| 入札済 | 入札書提出後 | 結果待ち |
| 受注 | 落札・契約締結 | 施工本部への引き渡し |
| 敗退 | 不落札 | 敗退分析、次回対策 |
| 中止 | 発注中止等 | 記録保存 |

#### 3.1.2 案件登録情報
| 項目 | 必須 | 説明 |
|------|:----:|------|
| 案件名 | ○ | 工事名称 |
| 発注機関 | ○ | マスタから選択 |
| 工事場所 | ○ | 都道府県・市区町村 |
| 工種 | ○ | 海上工事・陸上工事・エネルギー等 |
| 概算金額 | △ | 予定価格または推定額 |
| 入札方式 | ○ | 一般競争・指名競争・総合評価 |
| 入札日 | △ | 判明時点で入力 |
| 担当者 | ○ | 営業担当者 |
| 備考 | - | 自由記述 |

#### 3.1.3 案件カンバンボード
- ステータス別のカンバン表示（ドラッグ＆ドロップで遷移）
- カンバン上のカードに金額・入札日・担当者を表示
- フィルタ：発注機関別・工種別・支店別・担当者別

---

### 3.2 入札管理

#### 3.2.1 入札情報自動収集
- 電子入札システム（JACIC）からの発注情報自動取得
- 入札公告のRSS/スクレイピングによる自動通知
- キーワードフィルタ（工種・地域・金額帯）による絞り込み通知

#### 3.2.2 参加資格自動チェック
以下の参加資格要件を自動確認する機能：

| チェック項目 | 確認内容 |
|------------|---------|
| 経営事項審査 | 総合評定値（P点）の充足 |
| 等級区分 | 発注等級の該当性 |
| 地域要件 | 本店/支店の所在地要件 |
| 実績要件 | 同種工事の施工実績 |
| 技術者要件 | 配置予定技術者の資格・実績 |
| 指名停止 | 指名停止期間中でないこと |

#### 3.2.3 入札履歴管理
- 過去の入札結果（落札者・落札金額・落札率）をDB管理
- 競合他社の入札傾向分析
- 自社の落札率推移分析

---

### 3.3 総合評価点分析

#### 3.3.1 業務目的
総合評価方式入札での得点を最大化するため、過去の評価結果を分析し、加点項目の戦略的確保を行う。

#### 3.3.2 評価項目管理
| 評価区分 | 評価項目例 | 配点目安 |
|---------|----------|---------|
| 技術提案 | 施工計画の的確性 | 30点 |
| 技術提案 | 品質確保の取り組み | 20点 |
| 技術提案 | 安全対策 | 15点 |
| 企業の能力 | 同種工事の施工実績 | 10点 |
| 企業の能力 | 工事成績評定点 | 10点 |
| 配置予定技術者 | 資格・実績 | 10点 |
| 地域貢献 | 地域精通度・災害協定 | 5点 |

#### 3.3.3 加点シミュレーション機能
- 技術者配置パターンを変えた場合の得点シミュレーション
- 実績・成績評定点の組み合わせ最適化
- 総合評価点の予測値と競合比較

---

### 3.4 AI技術提案書生成

#### 3.4.1 業務要件
- 案件条件（工種・工事場所・規模・評価基準）を入力すると、過去の類似提案書を検索
- 検索結果をベースにAIがドラフト提案書を生成
- 生成結果は「施工計画」「品質管理」「安全対策」「環境配慮」のセクション別
- 技術者が編集・加筆して完成版にするワークフロー

#### 3.4.2 品質要件
- 生成されたドラフトの技術的正確性は技術本部がレビュー必須
- AI生成であることを社内で明示（提出書類にはAI生成表記不要）
- 過去5年以上の提案書データを学習ベースに使用

---

### 3.5 営業日報

#### 3.5.1 入力項目
| 項目 | 必須 | 説明 |
|------|:----:|------|
| 日付 | ○ | 自動入力 |
| 訪問先 | ○ | 発注機関名・担当者名 |
| 訪問目的 | ○ | 情報収集/案件打合せ/表敬/その他 |
| 商談内容 | ○ | 自由記述（音声入力対応） |
| 次回アクション | ○ | 期限付き |
| 関連案件 | △ | 案件紐づけ |
| 添付資料 | - | 写真・名刺等 |

#### 3.5.2 承認ワークフロー
```
営業担当が日報入力
    ↓
課長が確認・コメント（翌営業日まで）
    ↓
部長が確認（任意）
```

---

### 3.6 名刺管理・顧客情報管理

#### 3.6.1 名刺OCR
- スマートフォンカメラで名刺撮影→AI OCRで自動読取
- 読取項目：会社名・部署・役職・氏名・電話番号・メールアドレス
- 日本語名刺の認識精度95%以上
- 読取結果の手動修正機能

#### 3.6.2 顧客情報管理
- 発注機関の組織構造管理（部署・担当者の階層表示）
- 人事異動の追跡記録
- 接触履歴の時系列表示
- 関連案件の紐づけ
