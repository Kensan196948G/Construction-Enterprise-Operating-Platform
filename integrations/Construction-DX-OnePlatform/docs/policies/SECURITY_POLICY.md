# 🔐 情報セキュリティポリシー (Information Security Policy)

> Construction DX One Platform  
> 適用規格: ISO 27001 A.5.1 (情報セキュリティ方針) / A.5.2 (レビュー)  
> 作成: Loop #36 (2026-06-01) | 承認: CTO  
> 改訂サイクル: 年1回（または重大インシデント発生時）

---

## 📌 1. 目的

本ポリシーは、Construction DX One Platform（以下「本システム」）における情報セキュリティを確立・維持するための方針を定める。

本ポリシーの目的は以下のとおりである。

- 本システムが扱う建設会社の機密情報・業務データを不正アクセス・漏洩・改ざんから保護する
- ISO 27001 に基づく情報セキュリティマネジメントシステム（ISMS）を組織全体に適用する
- 事業継続性を維持し、インシデント発生時の影響を最小化する

---

本ポリシーは以下の全てに適用される。

| 対象         | 範囲                                                                         |
| :----------- | :--------------------------------------------------------------------------- |

## 🔑 3. 基本方針

### 3.1 機密性 (Confidentiality)

- 業務データへのアクセスは、業務上の必要性に基づき最小権限の原則に従い付与する
- JWT ベースの認証・認可を全 API エンドポイントに適用する
- 機密データの暗号化（保存時: AES-256、転送時: TLS 1.2+）を必須とする

### 3.2 完全性 (Integrity)

- データの改ざん防止のため、DB トランザクション整合性を保証する
- CI/CD パイプラインにセキュリティスキャン（Trivy / gitleaks）を組み込み、脆弱なコードのリリースを防止する
- 変更管理プロセス（Pull Request + レビュー + CI green）を全変更に必須とする

### 3.3 可用性 (Availability)

- SLA 目標: 稼働率 99.5%（計画停止を除く）
- RTO: 4時間以内、RPO: 1時間以内（`BCP_DRILL_PROTOCOL.md` 参照）
- 冗長構成: PostgreSQL streaming replication + Blue-Green デプロイ

## 🛡️ 4. 情報セキュリティ管理策

### 4.1 アクセス制御 (ISO 27001 A.9)

| 管理策         | 実装                                              |
| :------------- | :------------------------------------------------ |
| 認証           | JWT（RS256）+ 有効期限 15分（refresh token: 7日） |
| 認可           | RBAC（役割ベースアクセス制御）                    |
| 多要素認証     | 管理者アカウントに MFA 必須                       |
| セッション管理 | 30分無操作でタイムアウト                          |
| 特権アクセス   | DB 直接アクセスは DBA + 承認フロー必須            |

### 4.2 暗号化 (ISO 27001 A.10)

```text
保存データ: PostgreSQL TDE（Transparent Data Encryption）
転送データ: TLS 1.2 以上（TLS 1.0/1.1 無効）
シークレット: 環境変数（.env）+ GitHub Secrets
パスワード: bcrypt（コスト係数 12 以上）
```

### 4.3 物理・環境セキュリティ (ISO 27001 A.11)

- 本番サーバーへの物理アクセスは入退室管理対象
- 開発端末のディスク暗号化必須（BitLocker / FileVault）

### 4.4 運用セキュリティ (ISO 27001 A.12)

- ログ保持期間: 90日（監査ログは1年）
- Wazuh SIEM によるリアルタイム脅威検知（`monitoring/wazuh-rules.xml`）
- 週次脆弱性スキャン: Trivy（Docker イメージ）+ npm audit + pip audit
- gitleaks による秘密情報の誤コミット検出（CI 組み込み）

### 4.5 通信セキュリティ (ISO 27001 A.13)

```text
API Rate Limiting: 100 req/min/IP（API Gateway）
CORS: 許可オリジンホワイトリスト制御
X-Request-ID: 重複排除実装済み（Loop #28）
CSP ヘッダー: Content-Security-Policy 適用
```

### 4.6 システム取得・開発・保守 (ISO 27001 A.14)

- 全コード変更: Pull Request + CI green + セキュリティレビュー必須
- 依存パッケージ: Dependabot / Renovate による自動更新
- OWASP Top 10 対策: 入力検証・SQLインジェクション対策を実装標準に含める

### 4.7 サプライヤー関係 (ISO 27001 A.15)

- 外部 API 連携時は契約書にデータ取り扱い条項を含める
- Mocks Server によるサードパーティ API の安全な模倣・テスト

### 4.8 インシデント管理 (ISO 27001 A.16)

手順: `RUNBOOK.md §5` / `BCP_DRILL_PROTOCOL.md シナリオ 4` 参照

| フェーズ | 対応                                                |
| :------- | :-------------------------------------------------- |
| 検知     | Wazuh アラート → 5分以内通知                        |
| 封鎖     | 疑わしい IP の即時ブロック（ufw）                   |
| 調査     | ログ保全・Wazuh 解析                                |
| 報告     | CTO + Security へ即時通知、24時間以内に事後レポート |
| 再発防止 | 原因分析 → ポリシー更新 → PDCA                      |

### 4.9 事業継続管理 (ISO 27001 A.17)

- BCP 訓練: 年2回（6月・12月）— `BCP_DRILL_PROTOCOL.md` 参照
- RTO 4時間 / RPO 1時間 の目標値を訓練で検証

### 4.10 コンプライアンス (ISO 27001 A.18)

- 個人情報保護法 / GDPR ガイドラインへの準拠
- 年次内部監査: `AUDIT_CHECKLIST.md` に基づき実施
- J-SOX 対応: IT 統制証跡の保管（1年以上）

## 📋 7. 違反時の対応

- ポリシー違反が確認された場合、CTO および HR に報告する
- 悪意ある違反（情報漏洩・不正アクセス）は法的措置の対象となる
- 自己申告による報告は、制裁を軽減する要素として考慮する
