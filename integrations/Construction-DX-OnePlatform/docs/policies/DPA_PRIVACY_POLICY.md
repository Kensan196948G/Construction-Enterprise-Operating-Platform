## 📊 プライバシー影響評価 (PIA) 手順

### 🔒 PIA が必要な変更の条件

以下のいずれかに該当する変更は PIA を実施すること:

1. 新たな個人情報カテゴリの収集開始
2. 既存個人情報の新規利用目的への転用
3. 第三者への個人情報提供開始
4. 自動化意思決定システムの導入
5. 大規模な個人情報処理システムの変更

### 🔍 PIA 実施フロー

```mermaid
flowchart TD
    A[変更要求] --> B{PIA 必要?}
    B -->|No| C[通常変更管理フロー]
    B -->|Yes| D[PIA 担当者アサイン]
    D --> E[データフロー分析]
    E --> F[リスク評価]
    F --> G{リスクレベル}
    G -->|High| H[Security + CTO 承認]
    G -->|Medium| I[Security 承認]
    G -->|Low| J[Dev Lead 承認]
    H --> K[PIA レポート作成]
    I --> K
    J --> K
    K --> L[実装 + 監視]
```

### 📝 PIA レポートテンプレート

PIA レポートは `reports/privacy/PIA_<機能名>_<YYYY-MM-DD>.md` に保存する。

```markdown
# PIA レポート: [機能名]

- 実施日: YYYY-MM-DD
- 担当者: [氏名]
- 承認者: [氏名]

## 1. 概要

## 2. 取り扱う個人情報

## 3. データフロー

## 4. リスク評価

## 5. 軽減策

## 6. 残存リスク

## 7. 承認
```

## 🚨 個人情報漏洩対応

| フェーズ    | アクション                        |      期限       |        担当         |
| :---------- | :-------------------------------- | :-------------: | :-----------------: |
| 検知        | Wazuh アラート → インシデント起票 |      即時       |       DevOps        |
| 初動        | 影響範囲特定・封鎖                |   1 時間以内    |  Security + DevOps  |
| 報告 (内部) | 経営陣への一次報告                |   2 時間以内    |      Security       |
| 報告 (行政) | 個人情報保護委員会への報告        | **72 時間以内** |     CTO + Legal     |
| 本人通知    | 影響を受けた個人への通知          |    速やかに     |  Security + Legal   |
| RCA         | 根本原因分析・再発防止策          |   2 週間以内    | Security + Dev Lead |

> ⚠️ 個人情報保護法 第 26 条: 漏洩等が生じた場合、個人情報保護委員会への報告義務あり
