### 2.3 特権IDの定義

本レビューにおける「特権ID」は以下を指す。

- システム管理者（sudo / root 権限保有者）
- データベース管理者（DBA: SUPERUSER / CREATEDB 権限保有者）
- クラウド/インフラ管理者（MinIO管理コンソール / Elasticsearch cluster admin）
- CI/CD管理者（GitHub Secrets 書込み権限保有者）
- セキュリティ管理者（Wazuh管理者 / ファイアウォール設定変更権限）

## ⚠️ 4. レビュー判定基準

### 4.1 継続可否の判定基準

| 判定     | 条件                                                           | 対応                                 |
| -------- | -------------------------------------------------------------- | ------------------------------------ |
| 継続     | 業務上必要、最終使用日90日以内、MFA設定済み、有効期限管理      | そのまま継続                         |
| 要対応   | MFA未設定、または有効期限切れ、または権限過剰                  | 30日以内に是正。是正不可なら削除     |
| 削除候補 | 最終使用日から90日以上使用実績なし                             | 部門責任者に確認後、削除または無効化 |
| 即時削除 | 退職者・異動者のアカウント、または不正使用が疑われるアカウント | レビュー完了を待たず即時無効化       |

### 4.2 詳細判定ルール

**90日未使用ルール（削除候補）**

```sql
-- PostgreSQL: 最終ログイン確認クエリ（例）
SELECT usename, valuntil, pg_stat_activity.state
FROM pg_user
LEFT JOIN pg_stat_activity ON pg_user.usename = pg_stat_activity.usename
WHERE pg_user.usecreatedb = true OR pg_user.usesuper = true
ORDER BY usename;
```

```bash
# Linux: 最終ログイン確認
lastlog | grep -v "Never logged in" | sort -k3

# 90日以上未使用のアカウントを抽出
lastlog | awk -v date="$(date -d '90 days ago' '+%b %e')" '$0 < date {print $1}'
```

**MFA未設定（要対応）**

- GitHub: Organization の "Require two-factor authentication" 設定でMFA強制が有効であること
- 管理コンソール（MinIO / Grafana）: TOTP または FIDO2 設定済みであること
- MFA未設定の管理者アカウントは即時ログイン無効化し、設定完了後に再有効化する

**権限過剰（最小権限原則違反）**

- `RBAC_MATRIX.md` に定義された権限マトリクスと実際の権限割り当てを照合する
- 業務上不要な管理者権限（SUPERUSER / ADMIN 等）は即時剥奪する

### 4.3 対応優先度

| 優先度 | 内容                             | 対応期限                 |
| ------ | -------------------------------- | ------------------------ |
| P1     | 即時削除対象（退職者・不正疑い） | 検出後即時（24時間以内） |
| P2     | MFA未設定 / 権限過剰             | 検出後30日以内           |
| P3     | 90日未使用（削除候補）           | 部門確認後60日以内       |
