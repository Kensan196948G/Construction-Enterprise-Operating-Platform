## 1. 概要
### 1.1 目的
全部門データを統合するデータレイクを構築し、最終的にConstruction Digital Twin Platformとして現場→IoT→BIM/CIM→AI解析→経営分析→全社最適化のデータフローを実現する。

### 1.2 最終完成形
```
現場 → IoT → BIM/CIM → AI解析 → 経営分析 → 全社最適化
```

---

## 2. 機能要件

### 2.1 データ統合
- FR-CDL-001: 工事データ統合
- FR-CDL-002: 写真・映像データ統合
- FR-CDL-003: BIM/CIMモデルデータ統合
- FR-CDL-004: 人員・労務データ統合
- FR-CDL-005: 原価データ統合
- FR-CDL-006: 安全・品質データ統合
- FR-CDL-007: 資材・車両データ統合
- FR-CDL-008: ドローンデータ統合
- FR-CDL-009: IoTセンサーデータ統合
- FR-CDL-010: GPSデータ統合
- FR-CDL-011: AI解析結果データ統合

### 2.2 ETLパイプライン
- FR-CDL-020: 各部門システムからのデータ収集
- FR-CDL-021: データクレンジング・変換
- FR-CDL-022: スキーマ管理（データカタログ）
- FR-CDL-023: リアルタイム/バッチ処理の両対応

### 2.3 AI分析基盤
- FR-CDL-030: 統合データに基づくAI分析
- FR-CDL-031: ダッシュボード・レポート基盤
- FR-CDL-032: MLOpsパイプライン

### 2.4 デジタルツイン
- FR-CDL-040: 3D空間上への統合データマッピング
- FR-CDL-041: リアルタイムIoTデータ反映
- FR-CDL-042: シミュレーション機能

## 3. 非機能要件
- NFR-CDL-001: PB級データ対応
- NFR-CDL-002: データリネージ管理
- NFR-CDL-003: データガバナンス（アクセス制御・監査）

## 4. 技術スタック

| レイヤー | 技術 |
|----------|------|
| データレイク | Azure Data Lake / MinIO |
| ETL | Apache Airflow / dbt |
| ストリーミング | Apache Kafka / Azure Event Hubs |
| AI/ML | Azure ML / MLflow |
| 可視化 | Grafana / Superset |
| デジタルツイン | CesiumJS / Unity (WebGL) |
| データベース | PostgreSQL + TimescaleDB |
| 認証 | Entra ID + HENNGE SSO |

---

## 5. 統合要件
- 全部門システムからのAPI連携
- 共通マスタ管理（工事・組織・従業員・資材）
- 統一APIゲートウェイ

---

## 6. フェーズ計画
Phase1で基盤構築、Phase2でETL本格稼働、Phase3でデジタルツイン。
