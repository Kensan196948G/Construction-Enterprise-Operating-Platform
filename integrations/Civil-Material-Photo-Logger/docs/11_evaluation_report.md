## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | Civil-Material-Photo-Logger（現場材料写真記録アプリ） |
| 目的 | 現場の「材料がどこにあったか」を、写真＋属性情報で即時記録し、一覧・検索・台帳化する |
| 技術スタック | Swift 6 / SwiftUI（iOS 26+）/ SwiftPM Core / XcodeGen / GitHub Actions / CodeRabbit |
| 保存方式 | 端末内ローカル保存（Codable JSON + JPEG） |
| 出力方式 | CSV（UTF-8 BOM / CRLF）、JSON、PDF写真台帳、案件比較 |
| 配布経路 | TestFlight（試用中）→ App Store（未定） |
| ライセンス | MIT |
| 外部依存 | ゼロ（Apple標準フレームワークのみ） |
| 運用基盤 | サーバー・DBなし（Cloudflare / Neon は適用対象外） |

### 利用者

| 利用者 | 期待する利用 |
|---|---|
| 現場監督・現場技術者 | 搬入材料の撮影記録・数量確認・検収補助 |
| 協力会社・資材担当 | 搬入・仮置きの記録 |
| 本社・IT・DX部門（7名） | 台帳データの集約・運用管理・教育 |
| 経営層 | 材料管理の可視化・コスト把握 |

### 業務課題と提供価値

- **課題**: 写真・紙メモ・Excel・チャットに分散する材料記録の所在不明、後日の検収・数量確認の手戻り。
- **提供価値**: 電波の届かない現場でも使える完全オフライン記録。撮影と同時に属性を付与し、CSV/PDFで台帳化。外部送信なしのためデータ持ち出しリスクが低い。

### 完成段階・運用段階

- 完成段階: **機能面はベータ完了（v1.0.0準備完了）。** 22サービス・13モデル・275件のCoreテスト・16件のAppテスト・iPhone/iPad両UIが実装済み。
- 運用段階: **TestFlight試用中。App Store一般公開前。** 実データ利用者は存在（state.json 記録）。組織展開（600名）は未実施。

## 3. 強み（15件以上）

1. **完全オフライン動作** — 電波の届かない現場でも記録・保存・確認が完結する（実装・README）。
2. **外部送信ゼロ** — 自動通信コードなし。プライバシーとデータ持ち出し統制に有利（コード調査・プライバシー草案）。
3. **Core層のテスト密度** — 275件の単体テストがLinuxコンテナで全件PASS（2026-08-12実測）。
4. **データ全損経路の是正** — 破損JSONの要素単位救出＋元データ退避＋通知（PR #82・RecordStoreRecoveryTests）。
5. **CSV数式インジェクション対策** — `escapeUserText` で利用者入力列を無害化（CSVEscaperTests）。
6. **安全なバックアップ/復元** — 巻き戻しの孤立ファイル限定削除・写真欠落時の明示的継続（PR #84・BackupPhotoPruneTests）。
7. **スキーマ後方互換** — 未知rawValue・キー欠如を既定値へフォールバック（SyncStatus/TransactionType/InspectionStatus/materialPhotoFileNames）。
8. **決定的な並び替え・候補順** — 同着をidで決着（RecordSortService/SuggestionService）。
9. **数量のNaN/無限大拒否** — 入力経路とCore検証の二重防御（QuantityAdjuster/ValidationService）。
10. **アクセシビリティ基礎対応** — 44ptタップ領域・写真代替テキスト・権限拒否時の案内（PR #85）。
11. **iPhone/iPad両対応UI** — アコーディオン型ホームとサイドバー＋ダッシュボード（#78/#79/#71/#72）。
12. **QR/OCR/注釈/GPS/EXIF** — 現場入力の省力化と写真メタデータの証跡化。
13. **PDF写真台帳・案件比較・傾向分析** — 競合製品に引けを取らない出力機能。
14. **ゼロ外部依存** — サプライチェーンリスクが極小（importはFoundation/Apple標準のみ）。
15. **CI 3ゲート＋Swift 6** — Linux Coreテスト・iOS Simulatorテスト・CodeRabbit、言語モード統一（#92）。
16. **原因別エラーメッセージ** — バックアップ等の失敗を利用者が次行動を判断できる文言へ集約（BackupArchiveError.userMessage）。
17. **リリース基盤整備** — バージョン明示・CHANGELOG・Runbook・rollback方針（#97・docs/05）。
18. **文書と実装の突き合わせ文化** — 監査書（docs/04）に未確認項目を明記する運用が定着。

### 5.1 独自優位性

1. **完全オフライン・端末内完結**: 電波の届かない現場・地下・山間部で確実に動作し、データが社外へ出ない。
2. **材料記録への特化**: 数量・単位・取引種別（搬入/使用/返却）・残数量計算・傾向分析が一画面で完結。
3. **低コスト・ゼロ外部依存**: 月額ライセンスなし。Apple年会費と運用工数のみ。
4. **プライバシー設計**: 広告・解析・クラウド送信なし。

### 6.3 AI活用方針（チャット目的化しない）

原則:

1. **目的は時間削減・検索/判断支援・説明可能性・安全性・費用対効果**。チャット機能の追加は目的としない。
2. **AI不要領域を区別する**: 入力バリデーション・検索・絞り込み・集計・CSV無害化はルールベースのまま維持（現行実装が適切）。
3. 導入候補は「OCR誤認識補正」「写真自動分類」「自然言語検索（RAG）」「異常検知」「在庫予測」の順。
4. **RAG設計**: 記録・写真メタデータをベクトル化し、回答に必ず根拠（記録ID・写真・項目）と信頼度を付与。引用できない回答は返さない。
5. **構造化抽出**: OCR/QRは既存のルール処理を維持し、AIは「誤認識候補の提示」に限定。
6. **分類・予測**: 材料区分の自動提案・使用量予測は「提案」であり、確定は人間が行う。
7. **異常検知**: 数量急変・写真欠落・重複をフラグ化し、人間の確認を促す。
8. **モデル構成**: クラウドAPI（例: OpenAI系）または自社基盤。機密データの外部送信は禁止とし、必要なら社内/専用基盤でホスト。
9. **人間承認**: AI提案の自動反映は禁止。すべてのAI出力は確認後に入力欄へ反映。
10. **権限制御**: AI検索もEntra ID RBACと同一の権限でフィルタ。
11. **プロンプトインジェクション対策**: 入力値を命令として扱わない（データと命令の分離）、外部文字列のサンドボックス、出力の検証。
12. **個人・機密情報保護**: AI処理対象の写真・メモから個人情報を検出・マスク。ログへ機密を出力しない。
13. **監査**: モデル・プロンプト・入出力をログ保存し、監査ログと紐付け。
14. **誤判定時の責任分界**: AIは提案ツールであり最終判断は利用者。誤判定時の責任は運用規定で明確化。
15. **利用量・予算上限・停止手段**: 月間トークン/コール上限、コストダッシュボード、緊急停止スイッチ（キルスイッチ）を必須要件に。
