# 本番運用マニュアル（組織・管理者向け）

> 対象: IT・DX部門（約7名）、現場統括、経営層向け判断資料
> 最終更新: 2026-08-12

本書は、約600名の従業員がいる土木・建設会社で本アプリを本番運用するための
**組織運用手順・展開計画・データ管理方針・障害対応**を定めます。
単体のアプリ操作は `docs/08_user_manual.md` を参照してください。

---

## 1. 運用の前提と設計思想

| 項目 | 内容 |
|---|---|
| アプリの特性 | 完全オフライン・端末内保存。外部サーバーなし・外部送信なし |
| 配布経路 | TestFlight（現在）→ App Store（一般公開時） |
| データの所在 | 各利用者のiPhone/iPad端末内のみ |
| データの正本 | 端末内。組織としての正本は「バックアップファイルの共有先」で担保する |
| 開発・文書の正本 | GitHub（本リポジトリ） |

**重要な制約**: 本アプリにはクラウド同期・中央DB・ログイン認証がありません。
複数人での同時編集・承認ワークフロー・監査ログの一元管理は **将来機能（未実装）** です。
本運用マニュアルは、その制約の下でデータを失わず運用することを目的とします。

## 2. 配布・展開（デバイス管理）

### 2.1 配布手順

1. App Store / TestFlight からアプリを配布する（手順は `docs/05_release_runbook.md`）。
2. 原則として **会社管理のiOS端末（iPhone/iPad）** へインストールする。
3. 私物端末での利用を認める場合は、会社のMDM（Microsoft Intune等）による管理方針を別途定める。

### 2.2 MDM / Intune 推奨設定

| 設定 | 推奨値 | 理由 |
|---|---|---|
| 端末パスコード | 必須（6桁以上・生体認証併用） | 端末紛失時のデータ保護 |
| 端末暗号化 | 有効（iOS標準） | 写真・記録の持ち出し対策 |
| 紛失時リモートワイプ | 有効 | 現場写真・案件情報の漏えい防止 |
| アプリ削除制限 | 会社管理端末のみ適用 | 記録データの意図しない消去防止 |
| 位置情報 | 利用者の判断に委ねる（任意項目） | 位置情報は必須機能ではない |
| スクリーンショット制限 | 会社方針による | 機密現場の持ち出し統制 |

> MDMの適用可否・具体的な構成は会社のセキュリティ基準に依存します。未適用の場合は「未適用」として本節を保持し、適用後に更新してください。

### 2.3 協力会社への展開

- 公共工事80%の事業では、協力会社が記録を行うケースがあります。
- 協力会社端末への展開は、契約上のデータ取扱い（秘密保持・データ所有・削除義務）を定めてから行ってください。
- バックアップファイルの共有先は、会社が指定した場所に限定することを推奨します。

## 3. バックアップ運用（最重要）

本アプリのデータ保全は**端末内データ＋バックアップファイル**の二重化で担保されます。

### 3.1 責任の分担

| 対象 | 実施者 | 周期 |
|---|---|---|
| アプリ内バックアップ作成（月1回） | 現場利用者 | 月次 |
| バックアップファイルの共有先への格納 | 現場利用者 | 作成時 |
| 共有先の容量・保管確認 | IT・DX部門 | 月次 |
| 復元試験（別端末で復元できるか） | IT・DX部門（実機） | 月次 |
| 端末のiOS更新・MDM状態確認 | IT・DX部門 | 月次 |

### 3.2 バックアップファイルの取扱い

- ファイル形式: `.mplbackup`（1ファイルに記録JSON＋写真の圧縮なしBase64）
- 上限: 約200MB（写真が数十枚〜百枚程度の目安）
- 共有先の例: 会社共有ドライブ（SharePoint Online / OneDrive / ファイルサーバー）
- 暗号化: アプリ側では暗号化していないため、**アクセス制限のある共有先**を使うこと
- 保存期間: 会社の文書管理規定に従う（未制定の場合は3年を目安に検討）

### 3.3 月次バックアップ試験の手順

1. 対象端末で「バックアップを作成」→ 共有先へ保存。
2. 検証用端末（または同一端末の再インストール後）で「バックアップから復元」。
3. 記録件数・写真枚数・最終更新日時が一致することを確認。
4. 結果を運用台帳（`docs/06_operations_ledger.md`）へ記録。

## 4. データ保持・削除ポリシー

| データ種別 | 保持方針（推奨） | 備考 |
|---|---|---|
| 工事写真・材料記録 | 工事完了後、会社規定の保存期間（公共工事は発注者指定の期間を優先） | 写真は原本として証跡価値がある |
| 位置情報 | 記録と同一期間 | 記録に付随する属性 |
| 不要になった記録 | アプリ内で削除。削除後は端末から復元不可 | バックアップに残る場合は共有先からも削除 |
| 退職・協力会社離脱時の端末 | 会社管理端末はワイプ・回収、私物はアプリ削除＋バックアップ削除 | 個人情報保護の観点 |

> データ保持期間は、発注者との契約・会社の文書管理規定・関連法令（個人情報保護法等）を確認し、**法務部門の承認**を得て確定してください。

## 5. 監視・品質管理

### 5.1 監視項目（サーバーなしのため端末側・配布側を監視）

| 対象 | 確認方法 | 周期 | 担当 |
|---|---|---|---|
| クラッシュレポート | App Store Connect | 週次 | IT・DX |
| TestFlight フィードバック | App Store Connect | 週次 | IT・DX |
| 実機スモークテスト | `docs/05_release_runbook.md` §4 | リリース時 | IT・DX |
| CI 状態 | GitHub Actions（Swift Test / iOS Build / Secret Scan） | 随時 | IT・DX |
| 証明書・プロファイル期限 | Apple Developer Portal | 四半期 | IT・DX |
| ストレージ肥大（孤立写真の兆候） | 設定画面の使用量・端末空き容量 | 月次 | 現場 |

### 5.2 KPI（導入効果の測定）

| KPI | 目標例 | 測定方法 |
|---|---|---|
| 月間アクティブ利用者 | 現場担当の80%以上 | アンケート・現場ヒアリング（アプリは匿名のため利用統計なし） |
| 記録件数 | 月100件以上（部署別） | バックアップ/CSVの件数集計 |
| バックアップ実施率 | 月次試験対象の100% | 運用台帳 |
| データ消失インシデント | 0件 | 障害報告 |
| CSV台帳作成時間 | 従来比50%削減 | ヒアリング |

> 現状のアプリには利用統計（アナリティクス）がありません。導入効果は手動集計・ヒアリングで測定してください。

## 6. 障害対応とエスカレーション

### 6.1 障害分類

| レベル | 定義 | 例 | 対応期限 |
|---|---|---|---|
| L1 | データ消失・全端末で使用不能 | アプリ起動不能、記録が消えた | 即日対応（アプリ削除・再インストールをしないよう利用者へ案内） |
| L2 | 主要機能の一部不能 | CSV出力失敗、復元失敗 | 3営業日以内 |
| L3 | 軽微・表示不具合 | 表示崩れ、文言誤り | 次リリース |

### 6.2 初動対応

1. **データ消失の疑い**: 利用者へ「アプリを削除しない・再インストールしない」を案内。バックアップ共有先の最新ファイルを確認。
2. **クラッシュ**: App Store Connect のクラッシュログ・端末ログを取得。
3. **再現手順をIssueへ記録**（P0/P1判定は `docs/04_audit_and_backlog.md` の基準）。
4. 修正は通常のPRフロー（branch → PR → CI → レビュー → マージ）で行う。**緊急でもmain直接pushはしない**。
5. 配布済みビルドの差し戻しは `docs/05_release_runbook.md` §5。

### 6.3 エスカレーション

| 段階 | 担当 | 内容 |
|---|---|---|
| 1次 | IT・DX部門 | 問合せ受付・一次切り分け・利用者支援 |
| 2次 | 開発担当（GitHubリポジトリ管理者） | 原因調査・修正・リリース |
| 3次 | 経営層・現場統括 | データ消失・長期障害・法令対応の判断 |

## 7. 教育・利用開始

### 7.1 初期教育（現場向け 30分）

1. 基本操作（撮影→入力→保存→一覧→CSV出力）の実演
2. QR・OCR・注釈・GPSの使い方
3. バックアップ作成の実演（月1回の習慣づけ）
4. 注意事項（外部送信なし・アプリ削除でデータ消滅）
5. 運用台帳への記入方法

### 7.2 現場リーダー育成

- 各現場に「アプリ担当」を1名置き、月次のバックアップ試験・質問窓口を担当させる。
- IT・DX部門は月1回の巡回（リモート可）で定着度を確認。

## 8. 既存環境（Microsoft 365 / SharePoint 等）との連携方針

| 既存環境 | 現状の関係 | 将来の連携（未実装） |
|---|---|---|
| Microsoft 365 / Entra ID | 認証基盤としては未利用（アプリはオフライン単独） | 将来のクラウド同期・権限管理でEntra ID連携を検討 |
| SharePoint Online | CSV・PDF・バックアップの共有先として利用可能 | 自動アップロード（API連携）は将来機能 |
| Exchange Online | 連携なし | 通知（日報・承認依頼）の送信先として検討 |
| HENNGE ONE | 連携なし（アプリ自体にSSOなし） | 将来のクラウド版で検討 |
| Windows Server / DeskNet's NEO / DirectCloud | 連携なし | DirectCloud連携は将来機能 |
| FortiGate | 関係なし（外部通信なし） | 将来のクラウド連携時に通信制御を検討 |

> いずれも**現時点では連携していません**。将来連携の実現には要件定義・セキュリティ審査・開発投資が必要です（`docs/11_evaluation_report.md` のロードマップ参照）。

## 9. 費用試算（目安）

| 項目 | 費用 | 備考 |
|---|---|---|
| アプリ本体 | 無料（社内開発） | MITライセンス（OSS） |
| Apple Developer Program | 年間 11,800円（税別）程度 | 配布に必須 |
| TestFlight / App Store | 追加費用なし | — |
| サーバー・DB | なし | オフライン設計のため不要 |
| 共有ストレージ | 既存のM365容量を使用 | バックアップファイル格納 |
| 運用工数 | 月1〜2人日（IT・DX 7名のうち） | 月次試験・問合せ・リリース |
| 初期導入研修 | 数人日 | 現場巡回・資料作成 |

> 対比: 商用の工事写真管理クラウドは1人あたり月額数百円〜1,200円程度（例: 蔵衛門 1,200円/人）が公開例。600名全員に展開する場合は月額数十万円規模となり、**運用コストとの比較で導入判断**してください。
