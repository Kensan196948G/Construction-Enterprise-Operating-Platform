# 建設・土木統合マネジメントシステム＋BIM情報管理 要件定義書・詳細設計仕様書

## レポジトリ名

- `civil-construction-ims`：建築・土木の両方を含む統合マネジメントシステムを端的に示す名称。

***

## 1. 文書概要

本システムは、建設・土木事業者向けに ISO 9001、ISO 14001、ISO 45001、ISO 55001 を中核とし、ISO 19650 に基づく BIM/CIM 情報管理を統合的に運用するための業務基盤を構築することを目的とする。[1][2][3][4][5][6][7][8][9]

従来の紙、Excel、共有フォルダ、個別SaaSに分散した運用を整理し、文書管理、記録管理、是正処置、監査、教育訓練、リスク管理、資産管理、CDE連携を一元化することで、現場負荷を増やさずに規格準拠と業務効率化を両立することを狙う。[1][2][3][10][11]

***

## 2. 対象規格と位置づけ

| 規格 | 対象領域 | 本システムでの扱い |
|------|----------|--------------------|
| ISO 9001 | 品質マネジメント | 工事品質、施工計画、検査、不適合、是正、内部監査を管理する。[12][2][13][3] |
| ISO 14001 | 環境マネジメント | 環境側面、環境目標、法令順守、廃棄物・副産物、苦情・事故を管理する。[14][9][15] |
| ISO 45001 | 労働安全衛生 | 危険源、リスクアセスメント、ヒヤリハット、労災、教育、点検を管理する。[9][15] |
| ISO 55001 | アセットマネジメント | 資産台帳、保全計画、更新計画、LCC、リスクを管理する。[9][15] |
| ISO 19650 | BIM/CIM 情報管理 | EIR、BEP、CDE、承認ワークフロー、資産情報の引継ぎを管理する。[4][5][6][7][8] |

本システムでは、9001・14001・45001・55001を「組織運営の統合マネジメントシステム」とし、19650を「プロジェクト情報管理・BIM/CIM運用基盤」として重ねる二層構造を採用する。[1][2][5][7][8]

***

## 3. 背景と課題

建設業では、ISO 9001、14001、45001の統合運用や書類削減、現場負荷軽減が重要なテーマであり、実務上は統合マニュアルや共通帳票によるスリム化が行われている。[1][2][10][11]

一方で、BIM/CIMの普及により、ISO 19650が求めるCDEベースの情報管理、情報要求、整備段階から運用段階への情報引継ぎの重要性が高まっているため、従来のISO文書管理だけでは不十分になっている。[4][5][16][6][7][8]

主な現状課題は以下のとおりである。

- ISOごとに文書や帳票が分かれ、重複入力と二重管理が発生している。[1][2][11]
- 品質・環境・安全・資産・BIM情報が別システムに分散しているため、監査証跡とトレーサビリティが弱い。[5][7][8]
- 共有フォルダ中心の運用では、版管理、承認状態、レビュー履歴の可視化が不十分である。[5][7]
- 運用保守段階に必要な資産情報と竣工時情報の連携が弱く、55001と19650の接続が不十分である。[5][6][8][9]

***

## 4. システム化の目的

本システムの目的は、ISO要求事項に対応する統制運用を業務システム上に実装し、監査対応のための書類作成システムではなく、日常業務そのものがISO運用になる状態を実現することである。[2][3][10][11]

具体的な目的は次のとおりである。

1. 規格共通業務を統合し、文書・記録・監査・是正・教育の一本化を実現する。[1][2][10]
2. 工事・案件単位で品質、環境、安全、BIM情報を一体管理する。[3][4][5][7]
3. 資産台帳・保全計画とBIM/CIM情報を連携し、運用段階への情報継承を強化する。[5][6][8][9]
4. 内部統制、監査証跡、承認履歴を標準化し、審査・監査対応を効率化する。[2][5][7][10]

## 6. 業務要件

### 6.1 共通管理

- 統合方針、年度目標、部門目標、工事目標を階層管理できること。
- 規程、手順書、様式、記録様式を文書種別ごとに版管理できること。
- 申請、レビュー、承認、公開、廃止のワークフローを保持できること。
- 全イベントに対して操作ログ、承認ログ、変更履歴を保持できること。
- 内部監査計画、監査実施、指摘、是正、再発防止を一連で管理できること。
- マネジメントレビュー資料を自動集約できること。

### 6.2 ISO 9001

- 受注、設計、施工、検査、引渡しの各工程に対する標準プロセスを定義できること。[12][13][3]
- 工事単位に品質計画書、検査計画、検査成績、是正記録を保持できること。[12][17][3]
- 不適合、クレーム、再発防止、水平展開を管理できること。[2][13][3]

### 6.3 ISO 14001

- 環境側面と環境影響評価を工事単位・部門単位で管理できること。[14][9][15]
- 法令・協定・顧客要求事項の順守評価を登録できること。[14][9]
- 産業廃棄物、建設副産物、騒音振動、水質、粉じん等の管理記録を保持できること。[14][15]

### 6.4 ISO 45001

- 危険源とリスク評価、KY、作業別安全衛生計画を管理できること。[9][15]
- ヒヤリハット、労災、是正、再発防止のワークフローを保持できること。[9][15]
- 教育、講習、資格、健康診断、保護具点検を管理できること。[9][15]

### 6.5 ISO 55001

- 構造物、設備、車両、ICT機器等の資産台帳を管理できること。[9][15]
- 資産ごとに状態、リスク、保全履歴、修繕履歴、更新時期、LCCを保持できること。[9][15]
- 点検周期、保全計画、更新投資計画を可視化できること。[9][15]

### 6.6 ISO 19650

- 発注者の情報要求、組織要求、資産情報要求を管理できること。[5][16][6][8]
- プロジェクトごとにBEP、役割、命名規則、承認ステータスを定義できること。[5][6][7][8]
- CDEと連携し、作業中、共有、公開、保管の状態管理を実施できること。[5][16][7]
- 竣工時に運用管理向け資産情報へ引き継ぐデータセットを生成できること。[5][6][8]

### 7.2 代表ユースケース

1. 現場代理人が工事案件を登録し、品質計画、環境計画、安全計画、BEPを初期化する。
2. 関係者が各計画書をレビューし、承認後に現場へ公開する。
3. 日々の巡回、検査、KY、環境点検、是正、ヒヤリハットを現場から登録する。
4. BIM/CIM担当者がCDE上の成果物レビュー結果を記録する。
5. 竣工時に品質記録、引渡記録、資産情報、BIM情報を引継ぎパッケージとして出力する。

## 10. システム方式

### 10.1 全体方式

Webアプリケーション方式を採用し、統合ポータル、業務API、バッチ、ファイルストレージ、外部連携基盤で構成する。BIM/CIM情報管理はCDEと疎結合連携し、ISO運用のコアデータは自社基盤側で保持する。[5][16][7][8]

### 10.2 推奨実装技術

| レイヤ | 推奨技術 | 補足 |
|--------|----------|------|
| フロントエンド | React + Next.js | 管理画面、承認画面、ダッシュボード、モバイル対応を実装しやすい。 |
| UI | TypeScript, Tailwind CSS, shadcn/ui系設計 | 業務UIの統一、保守性、コンポーネント化に向く。 |
| BFF/API | NestJS または FastAPI | 権限制御、監査ログ、外部連携APIを実装しやすい。 |
| DB | PostgreSQL | トランザクション、JSONB、全文検索、監査用途に適する。 |
| 検索 | OpenSearch もしくは PostgreSQL FTS | 文書検索、全文検索、監査検索に利用する。 |
| ファイル管理 | S3互換ストレージ / Azure Blob | 文書本体、帳票、添付ファイル保存に利用する。 |
| 認証 | Entra ID / OpenID Connect | 社内認証基盤との統合に適する。 |
| ワークフロー | アプリ内実装 + BPMN互換拡張余地 | 初期は軽量実装、将来拡張を考慮する。 |
| 通知 | Microsoft Teams / メール連携 | 督促、承認依頼、期限通知に利用する。 |
| 監視 | Azure Monitor / Grafana / Prometheus | 可観測性と運用監視を実現する。 |
| CI/CD | GitHub Actions | テスト、自動デプロイ、IaC連携に向く。 |
| IaC | Terraform | 環境差分管理、再現性向上に利用する。 |

### 10.3 技術方針

- 業務ロジックはAPI層に集中させ、画面依存を避ける。
- 共通業務をモジュール化し、規格別拡張は疎結合とする。
- ファイル本体とメタデータを分離し、メタデータ検索性を高める。
- イベントログベースで監査証跡を残し、追跡可能性を確保する。
- ISO 19650関連はCDE製品依存を避ける抽象化レイヤを設ける。[5][16][7][8]

規程、計画書、監査是正、BEP、引継ぎパッケージなど文書種別・オブジェクト種別ごとにフロー定義を切り替え可能とする。

### 11.6 API設計方針

- REST APIを基本とし、一覧・検索・登録・承認・出力を標準化する。
- `/api/v1/projects`、`/api/v1/documents`、`/api/v1/nonconformities`、`/api/v1/assets`、`/api/v1/bim/eir` 等のリソース設計とする。
- 監査証跡のため、更新系APIは必ず `who`, `when`, `before`, `after`, `reason` を記録する。
- CDE連携APIはアダプタパターンで実装し、製品差異を吸収する。

### 11.7 データベース設計方針

- 共通主キーはUUIDを採用する。
- 共通監査カラムとして `created_at`, `created_by`, `updated_at`, `updated_by`, `version_no`, `deleted_at` を持つ。
- マスタとトランザクションを明確に分離する。
- 添付ファイルはメタデータをDB、実ファイルをオブジェクトストレージに格納する。
- BIM情報コンテナはCDE側識別子と内部識別子を併記する。

### 11.8 通知設計

- 承認依頼
- 差戻し通知
- 是正期限超過
- 教育期限切れ
- 点検期限超過
- CDEレビュー未処理
- マネジメントレビュー資料締切

通知チャネルはメール、Teams、アプリ内通知を標準とする。

### 11.9 帳票・出力設計

- 品質計画書
- 環境管理計画書
- 安全衛生計画書
- 内部監査報告書
- 是正処置報告書
- 教育台帳
- 資産台帳
- 保全計画表
- BEP
- 引継ぎパッケージ一覧

PDF・Excel・CSVの各出力を可能とし、監査提出用途に備えて版情報と出力日時を埋め込む。

## 13. 開発・導入方針

段階導入が望ましく、以下のフェーズを推奨する。[1][2][3][10][11]

1. フェーズ1：共通基盤＋ISO 9001＋14001
2. フェーズ2：ISO 45001 追加
3. フェーズ3：ISO 19650 / CDE連携
4. フェーズ4：ISO 55001 と引継ぎ・保全連携
5. フェーズ5：分析高度化、ISMS/BCP等の追加

この順序は、建設業で9001と14001の統合やスリム運用から着手する事例が見られること、およびCDEを含む19650対応が別の設計論点を持つことに整合する。[2][3][10][11][5][7][8]

## 14. リスクと設計上の留意点

- 規格要求を過剰にシステム化すると現場負荷が増えるため、入力最小化と帳票共通化を徹底する必要がある。[2][3][11]
- BIM/CIM連携をCDE製品依存で設計すると移行困難になるため、抽象化レイヤが必要である。[5][16][7][8]
- 55001との接続を見据え、竣工時情報を資産台帳へ引き継げるデータモデルを初期から持つ必要がある。[6][8][9]
- 承認ワークフローと監査証跡を後付けにすると統制不備となるため、コア機能として初期実装すべきである。[2][5][7][10]

## 15. 推奨結論

システム名称・レポジトリ名は、社内向けには `kensetsu-ims-bim-platform`、業務アプリ名としては `ISO IMS CDE Suite` など二層で持つ構成が扱いやすい。

システム構築方針としては、まず「統合文書管理・ワークフロー・監査証跡」を共通基盤として構築し、その上に 9001、14001、45001、55001 をモジュール化し、19650 は CDE連携アダプタと情報要求管理を独立モジュールとして重ねる構成が最も保守性と拡張性が高い。[1][2][3][5][7][8][10]
